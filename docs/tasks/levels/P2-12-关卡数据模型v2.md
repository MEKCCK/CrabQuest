# 需求 P2-12：关卡数据模型 v2 落地

- 优先级：P2（数据层扩展）｜ 前置：P1-02（错误码 schema 同批模式）｜ 依赖方：P3-17/21/22
- 来源：v3 §3.2-3.3；docs-review/L3-A2-pipeline.md §3

## 目标

关卡 TOML schema 扩展到 v2：新增 kind / expect_panic / hint_unlock / is_boss / trim_lines / options / answer_index / link 字段，全部 `#[serde(default)]` 兼容旧文件，加载时校验。

## 背景（实测事实）

- 当前 Level 模型只有 starter_code / expect_output / expect_error_code 三个内容字段，无法表达选择题、panic 关、Boss 关。
- rust-quiz 转化需要 options/answer_index（选择题型）；「制造指定 panic」需要 expect_panic；Boss 机制需要 is_boss 显式标注（不靠 tier 推断）。

## 需求范围

1. **新增字段**（全部 `#[serde(default)]`）：
   - `kind`：缺省 "code"；"quiz" = 选择题（v1 数据层先支持，交互 P3-21 复议）；
   - `expect_panic`：panic 消息子串匹配（优先于 expect_output，交互 P3-22）；
   - `hint_unlock: Vec<u32>`：与 hints 等长，失败次数阈值（P2-11）；
   - `is_boss: bool`：Boss 关显式标注（P3-17）；
   - `trim_lines: bool`：比对前每行去尾随空格；
   - `options` / `answer_index`：quiz 型必填（2-6 项、0-based）；
   - `link`：可选（rust-course 素材必填）。
2. **expect_output 规范化语义**（落码 validate）：两端 trim + CRLF 归一化（`\r\n`→`\n` 先于 trim）+ 行序敏感 + 行尾空格敏感（trim_lines 打开才宽松）+ 空串 = 只要求编译运行成功。
3. **加载校验**（game-data）：quiz 型 options 2-6 项且无重复、answer_index 界内、hint_unlock 与 hints 等长、expect_output 无 `\r`、source 存在性。

## 验收标准

- [ ] 旧 15 关 TOML 不加字段解析结果与现在完全一致（兼容回归）。
- [ ] 非法数据校验用例全过：options 1 项 / answer_index 越界 / hint_unlock 长度不符 → 加载报错（中文）。
- [ ] expect_output 比对：CRLF 输入通过、行尾空格默认不通过、trim_lines=true 时通过。
- [ ] 新增字段单测覆盖（§11.2）。
