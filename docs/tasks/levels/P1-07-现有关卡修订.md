## CJK 输入约束（P1-06 联动，关卡生产硬性规范）

背景：egui-miniquad 无 IME 通道（`egui-miniquad lib.rs:208` `ime: _`），编辑器内中文输入不可用（可粘贴）。
这是窗口后端能力边界，不是 bug，不做编辑器内中文输入（P3-20 再调研）。因此**所有关卡设计必须遵守**：

1. **可编辑代码不要求玩家输入 CJK 字符**：任何让玩家写出的修复代码，禁止包含中文。玩家可能输入的只有 ASCII。
2. **需要中文输出的关**（`expect_output` 含 CJK）：`starter_code` 必须**直接内嵌字符串字面量**
   （如 `const FAIL_MSG: &str = "解析失败";` 或预置的 `println!("…")`），玩家只改调用方式或复制粘贴，
   不得要求手打中文字符。hint 文案同样应引导使用内嵌字面量（如引用 `FAIL_MSG`），避免玩家照抄中文。
3. **新增关卡验收加一条 CJK 扫描**：解析 `assets/levels/*.toml`，凡 `expect_output` 含 CJK 的关，
   断言 `starter_code` 内含 CJK 字符串字面量（且应覆盖输出文本）；违反即打回。
4. **不得新增「自由输入中文输出比对」关卡类型**；编辑器首次进入显示一行弱提示
   「代码编辑器不支持中文输入法，中文内容请复制粘贴」（已由 P1-06 在 `app_ui.rs` 实现，只显示一次）。

示例（10-l2-result 已按此修订，P1-06）：

```rust
const FAIL_MSG: &str = "解析失败"; // 字面量内嵌，玩家 Err 分支只写 ASCII

fn main() {
    let result = parse_number("not a number");
    println!("{}", result.unwrap());
}

fn parse_number(s: &str) -> Result<i32, std::num::ParseIntError> {
    s.parse()
}
```
