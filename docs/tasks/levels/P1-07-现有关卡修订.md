# 需求 P1-07：现有关卡修订（去剧透 + 三级 hints + source 复核）

- 优先级：P1（MVP 必修）｜ 前置：无 ｜ 依赖方：P2-13/14（改写规范先行）
- 来源：v3 §3.4-3.5、§4.1、§6.2；docs-review/L3-D2-pedagogy.md §1、L2-chinese.md D2

## 目标

现有 15 关达到文案规范：description 不泄露答案、全部补全三级 hints、source 字段准确。

## 背景（实测事实）

- **剧透**：10-l2-result 的 description/hint 直接写「用 match 处理错误」与整段答案代码；07-l1-clone 的 description 写「使用 s1.clone()」——题目文字直接泄露解法。
- **hints 不完整**：仅 3 关用了 hints 数组（且 08 只有 2 条），其余 11 关只有单条 hint；现有 15 关 description 均值 50 字、hint 均值 50 字，未达规范。
- **source 不准确**：05-l1-borrow 实为 The Book ch4（非 rustlings）；11-l3-lifetime 混两题；08-l2-vec 无原题（L2 已点名）。

## 需求范围

1. **去剧透修订**（10-l2-result、07-l1-clone 必改）：description 只写「症状 + 目标输出 + 涉及概念名」三要素（≤80 字），删除修复动作表述；修复代码只允许出现在 hints[2]。
2. **三级 hints 补全**（11 关）：hints[0] 概念引导（≤40 字、无代码无 API 名）→ hints[1] 章节链接（≤60 字、rustwiki 白名单）→ hints[2] 代码片段（≤3 行 + ≤40 字说明）；沿用现有 hint_step 手动逐级揭示机制（P2-11 前不引入失败联动）。
3. **source 复核**：15 关 source 字段按 §3.5 统一格式 `<仓库> (<相对路径>, <版本/主题>, <许可后缀>，[改编说明])`；05-l1-borrow 改标 The Book ch4、11-l3-lifetime 注明混合来源、08-l2-vec 标注自编。
4. **CI 启发式（可选先行）**：description 出现 `clone()` / `&mut` / `let mut` / `match` 等关键词告警人工确认。

## 验收标准

- [ ] 10-l2-result、07-l1-clone 的 description/hint 无修复关键词与答案代码（grep 断言）。
- [ ] 15 关全部有三级 hints（数组长度 = 3，或单条 hint + 说明为何不设多级）。
- [ ] 每关 hints[1] 的链接在 rustwiki 白名单内且实测 200。
- [ ] 15 关 source 字段全部符合格式规范（正则校验）。
- [ ] 修订后 `cargo test --workspace` 全绿（game-data 关卡解析测试通过）；已通关存档不受影响（id 不变）。

## 依赖 / 风险

- 依赖：无（hints 数组机制已实现，见 PR #1）。
- 风险：去剧透可能让关卡更难 → 验收需同时确认「broken 版仍触发预期错误码、fixed 版仍输出 expect_output」（防止改文案时改坏代码）。
