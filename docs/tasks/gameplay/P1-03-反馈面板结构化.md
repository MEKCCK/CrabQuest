# 需求 P1-03：反馈面板结构化（ErrorCard）

- 优先级：P1（MVP 必修）｜ 前置：P1-01、P1-02 ｜ 依赖方：P3-19 行号跳转
- 来源：v3 §5.4、§7.7；docs-review/L3-C2-save-ui.md §2、L3-D2-pedagogy.md §3

## 目标

错误反馈从一维字符串列表升级为结构化卡片：错误码徽章 + 行号 + 中文解释 + 修复方向 + 可折叠原文，多错误分层展示，失败语气去挫败化。

## 背景（实测事实）

- 当前 FeedbackData.feedback 是 `Vec<String>`，错误信息平铺，无法区分错误码/行号/原文，面板不可交互。
- 「❌ 未通过」的失败措辞对初学者有挫败感（v3 定稿改「🔧 还差一点」）。

## 需求范围

1. **数据模型**：`FeedbackData` 增加 `errors: Vec<ErrorCard>`（结构化）、`expectation: Option<OutputDiff>`（输出不符两栏 diff）、`panic: Option<String>`（分类标题 + 净化消息）、`unlocked_next`、`hearts`；`ErrorCard { code, line, summary, zh, fix, example, link, hint_index }`。
2. **展示优先级**（自上而下）：① 错误码徽章 + 行号 + 中文标题（每错误一卡）；② 中文解释默认展开；③「怎么改」默认折叠；④ rustc 原文默认折叠（CollapsingHeader monospace 灰字）；⑤ 多错误默认只展开第一条，其余折叠「还有 N 个错误」；⑥ panic 卡片；⑦ 输出不符两栏 diff 逐行着色。
3. **三屏递进**：编译失败自动弹出第一屏（错误码+人话+行号），第二屏（为什么错+中文链接）与第三屏（修复+示例）不自动展开。
4. **语气**：「❌ 未通过」→「🔧 还差一点」。
5. **链接降级**：offline 标志时链接区隐藏为灰字提示，点击失败弹 toast 不崩溃（配合 P1-02 link/link_zh）。

## 验收标准

- [ ] 单错误：卡片含徽章/行号/zh 展开/原文折叠，均可独立开关。
- [ ] 多错误（≥2）：默认仅第一条展开，其余折叠且可逐个展开。
- [ ] 输出不符分支显示两栏 diff，行着色。
- [ ] panic 分支显示分类标题，原文折叠。
- [ ] 无 E 码错误显示 fallback 兜底卡（非空白）。
- [ ] 反馈面板在返回编辑器后保留（底部固定区域）。

## 依赖 / 风险

- 依赖：P1-01（数据结构来源）、P1-02（zh/fix/example 字段）。
- 风险：egui 折叠组件（CollapsingHeader）在长中文文本下的性能 → 卡片正文 ≤200 汉字上限约束。
