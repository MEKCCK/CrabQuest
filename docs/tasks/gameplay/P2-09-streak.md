# 需求 P2-09：Streak 连续游玩日

- 优先级：P2（机制扩展）｜ 前置：P1-04（字段进存档）｜ 来源：v3 §7.4；docs-review/L3-C1-gamification.md §1.4

## 目标

记录连续活跃日（纯展示无奖励），日期算法正确，杜绝跨月 bug。

## 背景（实测事实）

- rust-quest 的 `y*372+m*31+d` 日期算法有跨月 bug（2-28 → 3-01 会错误断链）——移植必须重写。
- 活跃行为定义：通关 / 查看 hint / 复习回血。

## 需求范围

1. **规则**：昨日活跃 → +1；同日幂等；更早或首日 → 重置 1；连续游玩日纯展示，无奖励。
2. **日期算法**：用 chrono `num_days_from_ce()`（推荐）或 std 纯函数 Hinnant 公式；禁 rust-quest 公式。
3. **存档**：streak_days + last_played_date（P1-04 已含；口径按 §8.4 二选一定稿）。
4. **展示**：UI 状态栏显示（如「🔥 连续 3 天」），无额外交互。

## 验收标准

- [ ] 跨月单测：2-28→3-01 不断链；12-31→1-01 不断链（§11.4 用例）。
- [ ] 同日多次活跃只 +1。
- [ ] 断档（隔 2 天）重置为 1。
- [ ] 无 chrono 时用 std 实现也能通过相同单测（算法可替换）。
