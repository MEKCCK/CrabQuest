# 需求 P1-04：存档版本化与迁移（杜绝静默丢档）

- 优先级：P1（发布前必修）｜ 前置：无 ｜ 依赖方：P2-08/09/10（新字段进存档）
- 来源：v3 §8；docs-review/L3-C2-save-ui.md §1、L2-gamification.md C2

## 目标

存档带版本号，旧档自动迁移不丢数据；未来版本过高时 fail-fast 报错而不是静默清档。

## 背景（实测事实）

- 当前 `SaveData` 5 字段**无 version**：字段改名/类型变更 → `CorruptSave` → 整档归零静默丢失，无备份无提示。
- save() 已有 tmp+rename 原子写（优于 rust-quest），但无 .bak。
- rust-quest 教训：未知版本静默丢档是其 schema v6 迁移踩过的坑，本项目不学。

## 需求范围

1. **version 字段**：`CURRENT_SAVE_VERSION = 1`；旧存档（无 version）读出 0 进入迁移链。
2. **v0→v1 迁移**（纯函数，迁移后立即回写落盘）：
   - version = 1；hearts 显式补 3（serde default 给 0，需显式补起始心，不得用 default 兜）；
   - streak_days = 0、last_played_date = None（无法回推历史，从零开始不惩罚）；
   - completed_steps = 由 `level_states` 中 state==Passed 的 id 生成 `"{id}:pass"`（老玩家记录不丢 XP 语义）。
3. **fail-fast**：`version > CURRENT` → `Err(CorruptSave("存档版本 {v} 高于游戏版本，请升级游戏"))`，原文件不被修改。
4. **.bak 备份**：save() 写入前把旧档复制为 `save.toml.bak`（人工恢复通道）。
5. **新字段全集**（`#[serde(default)]`）：version / player_name / hearts / streak_days / last_played_date / completed_steps / achievements / practice_unlock_all / victory_celebrated / boss_states；LevelProgress 加 best_time_ms / hints_used。

## 验收标准

- [ ] 迁移矩阵 5 条全过：① v0 真实形状 → version==1、hearts==3、completed_steps 正确、未通关关保持 unlocked；② version=99 → Err 且原文件未动；③ v1 roundtrip 全字段相等；④ completed_steps 仅 Passed 进集合；⑤ 极简 TOML（仅 xp=5）→ 迁移成完整 v1 不报错。
- [ ] save 后存在 .bak 且内容为旧档。
- [ ] 迁移后立即落盘（进程崩溃不丢迁移结果）。

## 依赖 / 风险

- 依赖：无；但 P2-08/09/10 新增字段必须先经本需求框架（避免再次无版本演化）。
- 风险：字段口径冲突（§8.4 五处二选一：last_played_date vs last_day、boss_states 取舍、seen_error_codes 补充、hints_used Vec vs u32、fail_count vs attempts）——落地时先定稿再编码。
