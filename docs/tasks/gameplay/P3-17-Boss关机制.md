# 需求 P3-17：Boss 关机制（四段）

- 优先级：P3（玩法）｜ 前置：P2-12（is_boss 字段）｜ 来源：v3 §7.5；docs-review/L3-C1-gamification.md §3.1

## 目标

四段 Boss 关机制：is_boss 显式标注、尝试配额分档 XP、失败不扣心、提示默认禁用（fail_count≥5 解锁兜底）。

## 背景（实测事实）

- L3-C1 明确裁决：**L0 不设 Boss**（入门层全是教学关），Boss 机制仅启用 L1-L4 层末关（现有 15 关下为 07-l1-clone / 10-l2-result / 12-l3-trait / 14-l4-lifetime-trap；扩展后为 21/33/44/53）。
- 混合概念约束：Boss 关覆盖本层 ≥3 知识点，但 broken 版只允许 1 个预期错误码（避免多码取舍歧义）。
- 四段主题：第一段所有权与克隆（E0382 混合）/ 第二段错误处理（E0277）/ 第三段 trait 与泛型（E0277+E0282）/ 第四段生命周期（E0597/E0106/E0505）。

## 需求范围

1. **is_boss 标注**：显式字段（不靠 tier 末关推断）；现有 4 关改为 Boss 关（07/10/12/14），扩展后 21/33/44/53。
2. **尝试配额分档 XP**：首通 ≤4 次尝试 +50、>4 次 +30；不设硬上限（不锁关卡）。
3. **失败不扣心**（区别于普通关 −1）；combo 仍清零、total_errors 仍 +1。
4. **提示默认禁用**：错误码解释卡仍显示（教学核心不豁免）；fail_count ≥5 解锁 hint 兜底；完美/连击加成照常。
5. **前置 recap**：Boss 关 description 前 ≤100 字用基准术语重述相关概念（rust-quiz 题必备）。

## 验收标准

- [ ] 4 个 Boss 关 is_boss=true，broken 版各只有 1 个预期错误码。
- [ ] 首通 ≤4 次 +50、>4 次 +30（attempts 计数驱动，分档单测）。
- [ ] Boss 失败 hearts 不变（与普通关对比单测）。
- [ ] fail_count <5 时 hint 不可见；≥5 时解锁。
- [ ] recap 文本 ≤100 字且用 §6.1 基准术语。
