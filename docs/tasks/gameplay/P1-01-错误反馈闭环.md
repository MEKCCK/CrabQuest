# 需求 P1-01：错误反馈闭环（EUNKNOWN 兜底 + panic 净化 + 解析器边界）

- 优先级：P1（MVP 必修）｜ 前置：无 ｜ 依赖方：P1-03 反馈面板
- 来源：v3 §5.3；docs-review/L3-B2-parser.md、L2-error.md

## 目标

编译失败时**永不出现空白反馈**；运行时 panic 给出分类化中文提示；解析器对多错误码、warning、异常定位的取舍规则明确并可测。

## 背景（实测事实）

- 现网 bug：01-l0-print 的 format 参数错误无 E 码，当前解析器返回空列表 → 玩家看到空白反馈（第一关就会触发）。
- panic stderr 以空行开头，且含线程 id 与临时目录路径，直接展示很刺眼。
- E0621 的 --> 指向返回表达式行、E0601 指向文件末尾行，反直觉但为实测事实，不得"修正"。

## 需求范围

1. **EUNKNOWN 捕获**：trim 后以 `error:` 开头且不含 `[E` 的行 → 记为 `EUNKNOWN`（kind=NoCode），带首个 --> 行号；`validate()` 编译失败且 errors 为空 → 强制输出兜底文案，禁止空反馈。
2. **panic 净化与分类**：净化三步（去行首空白 → 剥临时目录路径 → 剥 `thread 'main' (线程id) panicked at` 头与 note 行，保留 `main.rs:N:M` 定位行）；8 类关键词分类（越界 / unwrap None / unwrap Err / ParseIntError / 溢出 / 除零 / 显式 panic / 分配失败），各配中文提示与修复方向；不命中走通用文案。
3. **优先级**：panic 分支 > 输出比对 > 错误码。
4. **多错误码**：allow_compile_fail 判定只取首条 E 码；展示最多 3 条，超出折叠「+N 条」。
5. **同码多 -->**：每错误只取第一个 -->（首使用点）。
6. **warning 区分**：warning 不生成错误卡片、不判失败（裸 rustc 下退出码 0）；`-D warnings` 提升的无码 error 走 EUNKNOWN。

## 验收标准

- [ ] 01-l0-print 编译失败时反馈面板非空（回归锁测试，断言 errors 含 EUNKNOWN 或 fallback 文案）。
- [ ] 15 个解析器 fixture 全部通过（含无码 2 类、panic 2 类、多码、双 -->、warning 交错、空 stderr）。
- [ ] panic 展示无临时目录路径、无线程 id，保留 `main.rs:N:M` 行。
- [ ] `cargo test -p game-core` 全绿，新增 Tier 1 静态 stderr 用例 ≥8 个。

## 依赖 / 风险

- 依赖：无（先于 P1-03，先保证数据正确）。
- 风险：rustc 版本间 panic 消息措辞漂移 → 分类只匹配关键词，不断言全文（message_contains 稳定子串）。
