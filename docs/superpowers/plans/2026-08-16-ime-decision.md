# P3-20 附录：IME 决策记录（中文输入法不可用）

日期：2026-08-16
来源：docs-review/L3-C2-save-ui.md §3.4（证据链）；v3 §7.8；P3-20 任务文档
状态：**已决策（方案①：维持现状 + 粘贴制）**，本记录为 P3-20 交付物

## 1. 背景与证据链（实测，非推断）

代码编辑器（`Screen::Level` 的 TextEdit）内 **fcitx/ibus 等输入法的组合输入不可用**，中文只能粘贴。这是窗口后端能力边界，不是 bug：

| # | 证据 | 位置 |
|---|---|---|
| 1 | `egui_input.event = ... Event::Text { ime: _, mutable_text_under_cursor: _ }` —— **IME 字段恒为 None** | egui-miniquad 0.16.0 `src/lib.rs:208-209`（注释明示 `// no IME`） |
| 2 | miniquad 事件通道只有 `char_event(&mut self, _character, _keymods, _repeat)`，**无 IME/组合事件回调** | miniquad 0.4.11 `src/event.rs:182` |
| 3 | egui 0.31.1 TextEdit 虽处理 `Event::Ime`（候选窗/组合串），但经本后端**收不到任何 IME 事件** | egui 0.31.1 builder.rs（`cargo tree` 锁定版本） |

依赖链：`egui-macroquad 0.17.3 → egui 0.31.1 / macroquad 0.4`（Cargo.lock 实测）。

## 2. 候选方案对比

| 方案 | 改动量 | IME 支持 | 风险/代价 | 与约束符合度 |
|---|---|---|---|---|
| **① 维持现状（粘贴制）+ 编辑器弱提示**「代码编辑器不支持中文输入法，中文内容请复制粘贴」 | 零（提示已由 P1-06 落地并测试） | 无（粘贴可用） | 玩家需自行复制中文；学习成本低（需要中文输出的关，starter_code 直接给出字符串字面量，玩家只改调用/粘贴） | ✅ 零新增依赖、零架构改动、沙盒禁网哲学不破 |
| **② 换窗口后端：macroquad → wgpu/winit 直连** | 大（重写 `main.rs` 窗口/事件循环、egui 集成、macroquad 2D 层迁移；涉及 P2-11 动画等依赖 macroquad 的层） | 完整（winit 提供 IME 事件，egui 原生支持） | ① 触屏/字体/纹理管线全量回归；② 新增平台条件编译与输入差异处理；③ 与 v1 发布节奏冲突（P4-27 发布合规在即） | ❌ 违反「最小改动优先」；属于 v2 级架构决策 |
| **③ 「插入片段」按钮（预置中文字符串字面量，点击插入光标处）** | 中（编辑器工具条 + 片段预设表 + 插入 API；与 P3-19 光标 API 联动） | 部分（绕开输入法，非真 IME） | ① 片段表需随关卡内容维护，覆盖有限；② UI 复杂化；③ 仍不能自由输入任意中文 | ⚠️ 可作为 P3 后续增量，但**不能替代**方案①的关卡约束 |

## 3. 约束

- 不引入网络/AI 运行时依赖（禁网沙盒哲学，P4-24 bwrap 禁网络）。
- 不破坏沙盒哲学；无后台服务/输入法挂钩。
- **最小改动优先**：v1 发布临近，窗口后端/输入管线的架构级改动需另立决策（v2 路线）。
- 关卡设计已规避玩家手打中文（P1-06 验收项，持续有效）。

## 4. 决策：方案①（维持现状 + 粘贴制）

**理由**：
1. 证据链证明这是后端能力边界，非缺陷；规避成本最低。
2. 游戏文案全部预置（玩家零输入中文）；需要中文输出的关卡由关卡设计保证 starter_code 直接给出字符串字面量——**玩家被要求输入 CJK 的场景不存在**（P1-06 关卡验收标准，A 主题 53 关落地时同样检查）。
3. 方案②的 IME 收益与窗口后端重写的回归风险不成比例；方案③只是「有限片段」，无法消除对粘贴的依赖，且增加维护面。
4. 若未来 v2 换后端，本决策自动解锁——届时重开此记录即可。

**影响范围**：
- UI：编辑器首次进入显示一行弱提示（P1-06 已落地）：**「代码编辑器不支持中文输入法，中文内容请复制粘贴」**（灰色小字，仅显示一次，headless 测试覆盖）。
- 内容：关卡验收标准「可编辑代码不要求玩家输入 CJK」持续有效（P1-06 已写入 levels 工作区）。
- 无代码/依赖变更。

## 5. emoji 决策（P3-20 范围）

现状：内嵌字体（maple/Noto Sans SC 子集）**均无 emoji 字形**，`✅❌💡🔓🔒🔥❤️🦀⏳🗺` 等回退到 egui 内置 NotoEmoji/emoji-icon-font **单色渲染**（egui 0.31 颜色字形支持有限）。

**决策：接受单色回退，不新增彩色 emoji 字体，不删除现有 emoji 用法。**
理由：① 单色 emoji 与游戏深色 UI 风格统一，可读性无碍；② Noto Color Emoji 体积大（≥10MB）与子集化目标冲突；③ 现有文案 emoji 用法经 P2 系列验收，删除/替换会波及已测文案。未来若引入彩色 emoji 需专项评估（fontTools 子集化 + egui 颜色字形支持）。
